About

For more than a decade I've shipped production software where the stakes are real — patient-facing healthcare, banking platforms, state government services used by the public, and airline systems.

My work sits evenly across the stack: C# and ASP.NET Core services, APIs and middleware on the back end, and hand-built front ends — semantic HTML5, Sass, JavaScript and TypeScript, Angular and React — on the surface. I translate wireframes and designs into responsive, production-quality pages and components, and I work inside Bootstrap, Material and enterprise design systems rather than around them.

Accessibility is the thread through all of it. On state government applications I coded and remediated to WCAG 2.1 AA, testing with JAWS, keyboard-only navigation, axe DevTools and WAVE — because a public service only works if everyone can use it.

04

Process

How a piece of work moves from a requirement to a supported release — the same loop whether it's a new service or a legacy screen being modernized.

1

Understand & design

Start from the requirement and the design — wireframes, design-system components, and the users, including assistive-technology users, before writing code.

2

Build across the stack

Semantic, responsive front end matched to C# services, REST APIs and middleware — built with the design system's tokens and components, not one-off styles.

3

Test like a user

Keyboard-only passes, JAWS and NVDA screen-reader checks, axe DevTools and WAVE scans, plus unit tests — issues remediated, not just reported.

4

Ship & support

Source in GitHub, releases through Azure DevOps CI/CD pipelines, and production issues troubleshot across applications and environments after go-live.

Featured Work

Independent sample project · ASP.NET Core 8

Public Services Benefits Portal

A working code-sample portal I designed and built independently to show senior-level, hands-on work end to end: a resident applies for benefits through accessible forms, gets a confirmation, and checks application status — backed by real APIs, middleware and SQL Server examples.

The front end uses a small reusable design system built on semantic HTML5 and Sass design tokens, and the full journey is tested for keyboard use and screen readers.

  • Accessible forms — labelled controls, clear validation and error recovery, keyboard-first
  • Design system — Sass tokens, components and patterns documented for reuse
  • REST APIs & middleware — exception handling, security headers, logging
  • SQL Server examples — EF Core plus parameterized queries, schema and seed scripts
  • Tests included — xUnit test project covering the application flows
